## 1. 插件当前基线（v0.5.2，已核实）

### 1.1 架构
- **三维度空间**：8 宫（JB乾/JS坤/ZJ震/XX巽/HY坎/HG离/GZ艮/FX兑）× 8 子域 × 6 爻 = **384 checkpoints**。
- **成卦机制**：`sancai_mapping = { tian:['HG','HY','FX'], di:['JS','ZJ','GZ'], ren:['JB','XX'] }`，天/地各取 3 宫、人取 2 宫 → 6 爻对应 6 宫 → **64 卦型空间**（6 位二进制超立方体顶点）。
- **阴阳分流**：`quantileThresholds` 强制每爻阴阳分割，保证信息熵。
- **否决防爆**：`PROXY_SUBDOMAINS` 集合（如 `XX08` 缺口、`FX02` PB 等派生代理子域）**失去一票否决权**但仍参与评分，避免代理噪声引发否决爆炸（曾由 5→34/56 否决触发）。
- **空值修复**：`num('')` 已返回 `null`（原 `Number('')===0` 假填 0 的 bug 已修）。
- **标签修复**：`TRIGRAM_BY_LINES` 中 `001=震`（仰盂）、`110=巽`（下断）已纠正互换。

### 1.2 股票趋势现状（实测数据）
- 入口：`scripts/divine_batch_stocks.mjs` `--live` 在线模式，拉 56 只自选股腾讯行情（`qt.gtimg.cn`，字段 totalCap[45]/pb[46]/pe[39]/内外盘[7][8] 等）。
- **在线覆盖率仅 32.4%（126/384 活跃）** → 卦型多样性受限。
- **实测卦型 28 种**（N=56 理论期望 ~37.5）；**64 卦型现实可达需 ~300 只样本**（鸽笼原理上界 N=56，期望 ~37.5）。

### 1.3 关键约束（物理性瓶颈）
- 卦型多样性由**样本量**主导，非编码错误。当前 28/64 是数据覆盖不足的直接结果。
- 任何"扩充卦象种类到 64/1296"的目标，必须先解决**样本规模与数据覆盖**。

## 2. 对"1296新剥本-stock-trend-v2"的判读（假设，待文档确认）

### 2.1 "1296" 的数学含义（假设 A，主假设）
- **1296 = 6⁴**：暗示把当前"6 爻二元阴阳"扩展为**四维多趋势态**判定。
- 四维度候选分解（任一，均需文档确认）：
  - 维度 = {趋势方向, 趋势强度, 周期尺度, 确认度}，各分 6 级 → 6⁴ = 1296。
  - 或 36×36：两个复合轴（如 时间维 6×空间维 6）×（指标维 6×确认维 6）。
- **排除项**：若每爻取 6 态（强阳/弱阳/平/弱阴/强阴/变），则为 6⁶=46656，≠1296，故"1296"更可能是 4 个 6 级维度的组合，而非单爻 6 态。

### 2.2 "剥本" 的方法论含义（假设 B）
- **剥卦 = 第 23 卦（坤下艮上，五阴剥一阳）**，意象"剥落、层层褪去"。
- 推测方法论：**迭代剥离弱信号/噪声子域，收敛到唯一核心趋势**（peeling 隐喻）。
- 映射到架构：在现有 checkpoint 评分之上/之下新增一道**信号剥离聚合层**，逐轮剔除低权重/低置信否决，保留主干。

### 2.3 "stock-trend-v2" 的范围（假设 C）
- 指**趋势判定子系统**的 v2 重构（成卦前的信号评估与聚合），而非整套易经框架重写。
- 应与现有 `sancai_mapping`、`quantileThresholds`、`PROXY_SUBDOMAINS` 兼容，而非推翻。

> ⚠️ 以上 2.1–2.3 均为基于文档标题的**假设**，必须待原文校准。若原文定义不同，本方案第 4 节需整体调整。

## 4. 逐模块详细规划（仅规划，不含代码改动）

### M1 · 趋势态空间扩展
- **目标**：将每爻的 `{阴,阳}` 二元判定，升级为文档定义的 6⁴ 多维趋势态框架。
- **改动点**：
  1. `checkpoints.mjs`：扩展 `YAO_SEMANTICS_STOCK`（当前 6 爻×单宫）以支持多维度评级字段；新增维度枚举常量。
  2. `hexagram.mjs`：`TRIGRAM_BY_LINES` 与卦型编码需支持多维映射（当前 6 bit → 2⁶=64；新框架需定义 6⁴ 编码/降维到 64 展示的桥接）。
  3. `grading.mjs`：评分函数从二元加权改为多维趋势态加权。
- **未决**：6⁴ 的 4 个维度具体是什么、如何降维回 64 卦展示（供用户可读）。

### M2 · 剥卦式信号剥离流水线（新增）
- **目标**：实现"剥"的方法论——多轮迭代，每轮剔除权重/置信最低的否决信号，直至收敛到核心趋势。
- **改动点**：
  1. 新增 `lib/yijing/peeling.mjs`：`peel(iterations, threshold)` 对 384 checkpoint 做迭代收敛。
  2. `aggregator.mjs`：在聚合链中插入 peeling 阶段（位于子域评分后、成卦前）。
- **风险**：剥离阈值过紧 → 卦型塌缩回少数几类（重蹈 v0.5.1 前 4 冻结域覆辙）；需以 `scripts/analyze_hex_space.mjs` 监控每轮有效爻数 `k`，确保 `k` 不退化。
- **自校验**：复用 `analyze_hex_space.mjs`（每爻阳比、distinct 值、理论上界）观察 peeling 前后熵变化。

### M3 · 在线数据覆盖提升
- **目标**：缓解 32.4% 覆盖率瓶颈，提升卦型多样性。
- **改动点**：
  1. `adapters/stock-inputs.mjs`：扩大自选股样本（目标 ≥200，64 态需 ~300）。
  2. `adapters/quote.mjs`：补充指数上下文 `fetchIndexContext`（已具备骨架）与宏观层——明确**股市指数归 HY 五爻君位 / 国际国内经济形势归哪一层哪一爻**（v0.5.2 遗留待定项，本次需落定）。
- **未决**：目标样本规模（直接决定 64/1296 态可达性）；宏观/指数层的爻归属。

### M4 · 评分/否决权再平衡
- **目标**：1296 空间下防止否决爆炸复发。
- **改动点**：
  1. `checkpoints.mjs`：扩展 `PROXY_SUBDOMAINS` 集合定义（新增多维代理子域的免否决标记）。
  2. `quota.mjs`：否决预算/配额随维度扩展重新标定。
- **风险**：维度翻倍数后，派生代理子域数量激增，否决权策略必须同步收紧。

### M5 · 版本与发布路径
- **目标**：以 v0.6.x 发布，且不与另一会话的 v0.6.0 半成品冲突。
- **步骤**：
  1. 发布前 `git pull` 合并另一会话的 v0.6.0 半成品（stock-inputs.mjs / baselines.mjs / mapping.mjs 宫级简写 / factor-prompt.mjs），化解 0.5.2 提交 `6df0650` 的冲突。
  2. 三处版本号（package.json / manifest.json / SKILL.md）+ CHANGELOG 同步 bump。
  3. 沿用既有发布流程：`git archive HEAD` 干净打 tarball（排除未就绪文件）→ npm publish（显式 `--registry=https://registry.npmjs.org` + 临时 `--userconfig` + 2FA bypass token）。
- **风险**：若 v0.6.0 半成品仍半成品，需协商合并策略，避免把未完成代码带入发布包。

## 5. 关键瓶颈与样本量约束（数学论证）

- **鸽笼上界**：N 只股票最多产生 N 种不同卦型。N=56 → 上界 56，期望 ~37.5；实测 28 属合理偏低（覆盖率 32.4% 拖累）。
- **64 态可达**：需 N≈300（期望 ~64 且上界充裕）。
- **1296 态可达**：若 1296 为 6⁴ 全组合，则需更大样本或**分层抽样**（按维度均衡采样），否则大量态永不被观测。
- **结论**：M3（样本/覆盖）是 M1（1296 空间）生效的**前提**，顺序不可颠倒。
