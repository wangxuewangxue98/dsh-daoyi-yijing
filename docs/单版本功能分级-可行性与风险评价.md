> **状态**：正式分析稿（2026-10-22 22:50）——回答「只做一版插件、内嵌功能分级是否可行、风险如何」
> **约束**：本方案**只规划、不改动任何程序**。所有代码改动需经用户授权后实施。
> **基线**：`dsh-daoyi-yijing` v0.5.2（MIT，纯 JS 零求解器依赖，tarball 168.3 kB / 52 文件）
> **关联文档**：《商业化三档授权与管理端方案-暂定.md》（三档定价/后端/管理端细节）、《stock-trend-v2-设计方案-暂定.md》（维度定义）

## 0. 结论摘要

| 问题 | 结论 |
|---|---|
| 只做一版插件、内嵌功能分级，**可行吗**？ | **可行，且是本插件家族已验证的路线**——`dsh-motor-ai` 商业化授权全部在单包内完成（§1 有现场取证），技术门控先例有三个，daoyi 自身已有本地闸门先例 |
| **推荐吗**？ | **强烈推荐**。daoyi 纯 JS 零求解器依赖，不存在 motor-ai 家族"L0/L1L2 技术分包"的理由；单版本在维护成本、升级路径、市场条目三个维度全胜（§3） |
| **风险大吗**？ | **总体可控**。最大风险是**客户端软门控可被本地破解**（JS 可读可改）——这是形态固有的，无法根除、只能提高门槛；第二大风险是**付费算法随包分发被抄袭**——但算法早已在公开文档中，真正资产应是数据口径与持续更新（§4） |
| 一句话商业判据 | 单版本把付费价值放在「**层级深度 + 数据口径 + 持续更新 + 服务**」上，而非「隐藏算法」上，则该模式成立 |

## 1. 先例核实（现场取证，非记忆）

### 1.1 三个门控先例全部在位

| # | 先例 | 现场证据 | 证明什么 |
|---|---|---|---|
| 1 | `dsh-motor-ai`（npm `1.0.0-rc.18`，PolyForm-Noncommercial，63 文件） | `lib/license.mjs`（955 行）：三形态激活 = Ed25519 离线码 / `DM-XXXX` 在线口令（后端可吊销）/ JWT License Token；`tier ∈ {free,l1,l2,full}`；`tierAllows(tier, level)` 纯函数（license.mjs:497）；`queryActivation()`；离线宽限判定 | **单包内做商业分级完全可行**：一个 npm 包承载全部档位，档位由授权态决定，不由包决定 |
| 2 | `dsh-motor-ai-l0`（npm `0.6.5`，MIT，67 文件） | `lib/level-gate.mjs`：`tierOf(level)` 映射 `l0→free / l1→vip / l2→flagship`，注释明言「商业化钩子占位」；fail-fast 设计；零依赖可离线断言 | **门控模块的标准写法**已在家族内固化：纯函数、零依赖、快速失败、可被 `scripts/verify.mjs` 离线断言 |
| 3 | `dsh-daoyi-yijing`（本地 v0.5.2） | `lib/yijing/quota.mjs`（316 行）：本地 fail-closed 配额闸门 + `buildLlmQuotaExceededMessage()` 升级引导文案（含联系邮箱 13546196530@163.com 与「dshhub-market 口令市场」入口，quota.mjs:198-220） | **daoyi 已有闸门基建**：日限计数、越权引导、诚实边界声明三件套都在，缺的只是「授权态 → 能力矩阵」这一层 |

### 1.2 关键澄清：motor-ai 家族的两个包不是商业档位分包

- `dsh-motor-ai`（L1/L2 完整版）依赖 RMxprt + Motor-CAD **求解器**；`dsh-motor-ai-l0`（毫秒级广筛）**纯 JS 零求解器**——两者是**技术层分包**（求解器依赖拆分），共享 `@wangxue98/dsh-motor-ai-core`。
- **商业化授权（免费/收费）从不是靠分包实现的**，而是单包内 license.mjs 的授权态判定。
- daoyi 与 l0 同为纯 JS 零求解器依赖 → **没有技术分包理由**，单版本是自然形态。

## 2. 单版本架构设计（规划，不动程序）

### 2.1 分发形态

- **一个 npm 包**（`dsh-daoyi-yijing`）+ **一个 DSH 插件市场条目** + **一条版本线**。
- 商业化**不走市场定价**，走激活码体系——daoyi 现有文案已引用「DSH 插件市场（dshhub-market 口令市场）」（quota.mjs:202），与该形态自洽。

### 2.2 授权态 × 注册态 → 能力矩阵（单版本的核心：同一个包，四种用户态）

| 用户态 | 授权态 | 注册态 | 外层开放层级 | 组合空间 | 内嵌钻取 | 日限（推演调用） |
|---|---|---|---|---|---|---|
| **免费·免注册** | free | anonymous | L1–L3：(d,s,c) 域/分域/子域 | 6³ = 216 | ✗ | **9 次/日** |
| **免费·免费注册** | free | registered | L1–L3：(d,s,c) | 6³ = 216 | ✗ | **99 次/日** |
| **收费（完整）** | full | registered | L1–L4：(d,s,c,w) +微域 | 6⁴ = 1296 | ✗ | **9999 次/日** |
| **Plus** | plus | registered | L1–L4 + 内嵌 (y,j,b,a) | 6⁸ = 1,679,616 | ✓（元-节-基-原子钻取） | **9999 次/日** |

> 维度语义依据《§10 微域内嵌归因子树规范》方案A定稿；定价依据已确认方案（完整 ¥99/199/399/699、首定 ¥9.9/99/199/399；Plus ¥199/399/699/1299、首定 ¥99/199/399/699）。
> **双注册态（2026-10-23 确认）**：两个免费态同属 capability tier `free`、同维度 6³=216，**唯一差异是日限 9 vs 99**——注册态只放大免费档日限一个数量级，不开放任何新能力；免费注册凭据推荐「DR 免费注册口令」路线（复用既有口令基建，DSH 账号路线已现场核实不可行）。详见商业化方案 §2.4。

### 2.3 门控植入点（授权后的改动规划）

| # | 改动点 | 内容 | 复用先例 |
|---|---|---|---|
| G1 | 新增 `lib/yijing/license.mjs` | 复制改造 motor-ai `license.mjs`；**独立 Ed25519 密钥对**（防一串码解锁两个插件）；tier 解析 + `tierAllows` 纯函数 + 三形态激活 | motor-ai license.mjs |
| G2 | `tools/yijing/index.mjs` `registerYijingTools` | 入口 gate：divine 工具按 tier 限制层级深度；越权 → 降级 + `buildActivationGuide()` 引导升级 | l0 level-gate fail-fast |
| G3 | `lib/yijing/quota.mjs` 扩展 | 在现有 LLM 配额闸门旁加「推演调用日限」层：**free·免注册=9 / free·注册=99** / full=plus=9999，自然日重置；注册态由 license.mjs 激活态驱动 | 自身 quota.mjs |
| G4 | Plus 钻取工具 | 同包注册；非 plus 调用返回升级引导（不报错、不静默） | l0 tierOf 钩子 |

### 2.4 升级体验——单版本的核心商业优势

用户装**同一个包**，购买后**输入激活码即解锁**：零卸载、零重装、零数据迁移、零「装错包」客服工单。支持侧永远只有一版代码、一套测试、一条版本线。

## 3. 单版本 vs 多版本（三包）对比

| 维度 | 单版本（本方案） | 三包分包（trial/full/plus 各自发包） |
|---|---|---|
| 维护成本 | **1 份代码** | 3 份，每次改动 ×3 |
| 版本漂移 | 无 | 需强制同步，易出现「A 包已修 B 包未修」 |
| 市场条目 | **1 个** | 3 个，用户选择困惑 |
| 升级路径 | **输码即解锁** | 卸载旧包 → 装新包 → 重新配置 |
| 破解面 | 客户端软门控（同级） | 客户端软门控（同级，无差异） |
| 先例支持 | **motor-ai 单包内授权（已验证）** | 家族内无商业分包先例 |
| 代码体积 | 全量（daoyi 仅 ~168 kB，可忽略） | 各自略小 |
| 结论 | **除体积外全胜** | 仅体积一项占优，且可忽略 |

## 4. 风险评价（概率 × 影响）

| # | 风险 | 概率 | 影响 | 缓解措施 | 残留风险 |
|---|---|---|---|---|---|
| R1 | **客户端软门控可被本地破解**：JS 插件代码完全可读，懂技术用户可改本地文件绕过 tier gate | **高** | 中 | ① 在线口令/JWT 可后端吊销（motor-ai 已验证）；② 高价值下探能力与后端数据/口径校准绑定——纯破解得不到持续更新的口径表；③ 文档诚实声明（quota.mjs 已有「诚实边界」注释先例） | **无法根除**，只能提高门槛；需在商业预期中计入（破解者本就是低付费意愿群体） |
| R2 | **付费算法随包分发被抄袭**：Plus 钻取/微域命名规则对免费用户可见 | 高 | 中 | ① 算法体系已在公开 docs 文档化，本非秘密；② 真正资产 = 数据口径 + 行情适配 + 持续校准，抄袭者需自建校准链路；③ MIT 许可下作者控制的是服务（激活/口径/更新），不是代码本身 | 竞品可复制框架，难复制数据资产 |
| R3 | **免费档自噬**：免费 216 组合 + 99 次/日满足多数轻度用户 → 转化率低 | 中 | 高（收入） | ① 免费档止于 L1–L3（看不到微域/标的集群），股票用户核心价值自 L4 起——分界清晰；② **双注册态构成两级漏斗**：免注册 9 次/日（尝鲜）→ 免费注册 99 次/日（常用，先圈人再转化）→ 付费（深度）；③ 引导文案指向首定优惠价 | 需上线后实测转化率 |
| R4 | 单版本回归影响全量用户（一次坏发布打击所有档位） | 中 | 中 | 8 套测试 + `scripts/verify.mjs` 门禁已建立；发布前 tarball 与源码逐文件 diff 流程已固化（v0.5.2 验证过） | — |
| R5 | 授权后端单点故障（在线激活/吊销不可用） | 中 | 中 | Ed25519 离线码兜底（无后端可激活）；DM/JWT 在线形态可吊销——两形态并存 | 离线码不可吊销，泄露只能等过期止损 |
| R6 | Ed25519 私钥管理不当（泄露 → 可伪造激活码） | 低 | 高 | daoyi 独立密钥对（不与 motor-ai 共用）；私钥离线保存 + 备份策略 | 泄露须换密钥 + 全量重发码 |
| R7 | 日限计数本地可绕过（删/改计数文件清零） | 高 | **低** | 日限只防滥用、不承载付费价值；付费档 9999 实际不设防；quota.mjs 已如实披露该边界 | 可接受（与 R1 同源，但影响面小） |
| R8 | 与工作区 v0.6.0 半成品冲突 | 中 | 中 | 先合并 v0.6.0 基线，再落商业化改动 | — |
| R9 | 私域收款（金数据）纠纷无平台担保 | 中 | 低 | DM 码可吊销作为售后手段；激活前明示「虚拟商品激活后不支持退款」 | 小额纠纷自担 |

### 4.1 对 R1/R2 的诚实展开（这是该模式成立的前提认知）

- **R1 不是缺陷，是形态固有**：任何客户端软件（包括 motor-ai）的授权门控都可被本地破解。单版本不改变这一点，多版本也不改变。商业上正确的应对不是「假装不可破」，而是：**让付费价值的大头放在破解者拿不走的东西上**——后端数据口径、持续更新、可吊销的在线授权、服务响应。
- **R2 同理**：用户自己已把 384 检查点 / 1296 坐标体系写进公开分享的文档，算法不是护城河；护城河是**把体系跑通的数据链路与校准经验**。单版本分发与此判断自洽。

## 5. 分项可行性结论

| 维度 | 结论 | 依据 |
|---|---|---|
| 技术可行性 | **高** | 三个门控先例现场在位；daoyi 已有 quota.mjs 闸门基建；植入点明确（G1–G5） |
| 商业可行性 | **高** | 金数据私域收款 + `admin_dsh.py` 台账/口令按 `plugin_id` 参数化 + 管理端面板按插件行参数化——daoyi 注册即接入，无需新建系统 |
| 运营可行性 | **高** | 单版本 = 一套测试、一条版本线、一类客服问题；测试门禁与发布校验流程已固化 |
| 法律/合规 | **中** | daoyi 现为 **MIT**：不妨碍售卖激活码/服务，但也不禁止他人二次分发 npm 包（作者控制服务端即可）；可选改 PolyForm-Noncommercial（motor-ai full 先例）——**建议保留 MIT + 服务变现**，与「付费价值=服务」的判断一致；私域收款无平台担保已在 R9 列明 |

## 6. 实施要点（授权后按序执行，单版本下更简）

1. **P1 授权地基**：G1 license.mjs（新密钥对，私钥管理方案先行确认）。
2. **P2 能力门控**：G2 入口 gate + G4 钻取工具门控 + `buildActivationGuide`。
3. **P3 日限分层（两轴）**：G3 quota 按 tier × 注册态（免注册 9 / 免费注册 99 / 付费 9999，自然日重置）。
4. **P4 后端接入**：`admin_dsh.py` 注册 daoyi 台账 + `PASSCODE_PLANS` 加 plus 档与首定价。
5. **P5 管理端**：`DshPluginPanel` 选 daoyi 行即生效；加「授权档位分布」统计卡。
6. **P6 交易闭环**：金数据 SKU（首定/续费双链接）+ webhook 签发。
7. **Plus 前置**：移植 `microdomain-drill.mjs` + `verify_microdomain_drill.mjs`，跑通 §10.10 四组验收断言后 Plus 档方可开放。
8. 每阶段跑 daoyi 8 套测试 + `scripts/verify.mjs`；发布沿用 `git archive HEAD` 干净打包。

## 7. 最终结论

**单版本 + 功能分级：可行、推荐、风险可控。**

- 它不是激进尝试，而是把 `dsh-motor-ai` 已验证的单包授权模式平移到纯 JS 插件上——技术风险主要是工程量，不是可行性。
- 唯一需要诚实面对的是 **R1（客户端软门控可破）与 R2（算法可见）**：这两条决定了商业设计必须「**卖服务与数据，不卖隐藏算法**」。只要首定优惠价（¥9.9 起）降低试用门槛、层级分界（L3/L4）卡在股票用户的核心价值上，该模式成立。
- 剩余未决（不阻塞启动）：Ed25519 私钥管理方案、与 v0.6.0 半成品合并顺序、首定优惠实现机制（建议口令 `firstOrder` 标记 + 金数据双 SKU）。
